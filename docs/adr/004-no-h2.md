# ADR-004: No H2 — Testcontainers Postgres for all tests

**Status:** Accepted
**Date:** 2026-10-05

## Context

The Spring convention is H2 for tests, real Postgres for production.
This creates a dialect gap: queries that pass on H2 fail on Postgres
(partial indexes, JSON operators, `ON CONFLICT`), and vice versa.

## Decision

No H2 dependency. All database tests run against real PostgreSQL 16
via Testcontainers with Flyway migrations applied.

## Rationale

1. **The V1 migration uses a partial index** (unacknowledged anomalies).
   H2 can't validate it. Testing against a different database than
   production is testing a different system.
2. **Testcontainers is fast enough.** Container startup is seconds;
   the suite runs in well under a minute on CI.
3. **One fewer dialect to reason about.** `application.yaml` has dev
   and test profiles, but both point at Postgres.

## Consequences

- Tests require Docker. CI runners and dev machines must have it.
  Documented in CONTRIBUTING.md prerequisites.
- Slightly slower than H2. Worth it for dialect fidelity.
